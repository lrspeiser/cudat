Earlier 0.4.0 validation — 18 October 2026

Verified:
- Durable requester inbox, bounded evidence, heuristic diagnosis, acknowledgements and replay safety.
- Actual MCP stdio failure push -> requester fetch -> acknowledgement acceptance test.
- Linked checkpoint retry completes without changing the failed parent or its evidence.
- Concurrent duplicate retry keys create one job; mismatched options/active duplicates are rejected.
- Failed prerequisites block only dependents; checkpoint-resume dependency lineage is followed.
- Read-only dashboard failure endpoint preserves stored evidence.
- Shared CPU fixtures overlap; exclusive fixtures serialize; one cancellation preserves the other job.
- Shared admission checks consent, declared compute/VRAM, recent utilization, cushions and slot limits.
- 39 unittest tests on Windows Python 3.13 and Ubuntu 24.04 under WSL.
- CPU-only process lifecycle: ordered queue, failure propagation, queued/running cancel,
  descendant cleanup, hard timeout, impossible budgets and duplicate workers.
- Windows abrupt worker death recovery; Linux process-group cleanup.
- Progress SDK validation, phase/rate ETA, revised forecasts, terminal rejection.
- MCP stdio handshake, tool visibility, isolated submit/report/cancel/reorder/pause/resume.
- Dashboard read-only HTTP routes, bounded logs, host restrictions, missing data.
- Local control origin/token checks, stale-order rejection and hold/resume.
- Checkpoint pause -> short job -> checkpoint resume with exact completed-item ledger.
- Legacy schema migration, concurrent admission recheck and unsupported-pause rejection.
- Graceful worker handover and rejection of a second dashboard on the same port.
- Wheel built and installed in a clean Windows virtual environment.
- Installed commands launch; queued child -> progress SDK -> final report passed.
- Browser inspection of live queue, narrow layout and running-job log dialog.

Limitations:
- No end-to-end tests inside actual Codex, Claude Code or Gemini MCP clients.
- No new CUDA workload was launched for testing; the existing production workload was preserved.
- Windows Job Objects do not contain WSL-hosted GPU services.
- Linux detached descendants and abrupt worker death require operator recovery;
  restart is gated by --acknowledge-orphans for stale running records.
- Exact mobile-device emulation and a native non-WSL Linux host were not tested.
- No actual agent-client integration or PyPI publication is implied by these checks.
